# Git

## Repository

Репозиторий — это проект, за которым мы следим в Git и храним информацию

## Commit

Commit — это сохраненная точка состояния проекта

## Branch

Branch — это отдельная линия разработки внутри репозитория

## Merge

Merge — слияние веток внутри проекта

## Rebase

Rebase — переносит коммиты на новую ветку, переписывая историю

## Tag

Tag — это создание ярлыка на конкретном коммите

## Remote Repository

Remote repository — это проект, который находится уже не только в памяти Гит, но
и может быть вынес за пределы локального нахождения.

## Clone

Clone — это клонирование проекта из гитхаба 

## Fetch 

Fetch — это скачать изменения в проекте от другого разработчика, узнав эти изменения

## Pull

Pull — это скачать и применить изменения относительно файлов к текущей ветке

## Revert

Revert — это отмена изменений в коммите, созданием нового коммите об отмене

## Restore

Restore — удаляет изменение из рабочей зоны

## Reset

Reset — выполняет перемещение ветки/головной и может вносить изменения в промежуточной зоне

## Cherry-Pick

Cherry-Pick — это перенос коммита из одной ветки в другую без слияния веток

## GitHub Flow

GitHub Flow представляет собой main-ветку и короткие feature/*-ветки плавно перетека-
ющие в Pull Request, а после согласования через merge слияние в одну ветку
(main + feature-ветки + Pull Request).

## GitFlow

GitFlow представляет собой main-ветку для стабильных релизов, дл основной разра-
ботки имеется - develop-ветка, для новых функций используется feature/*-ветка,
для подготовки релиза - release/.., а для срочных фиксов hotfix/*-ветка.
(main + develop + feature + release + hotfix).

## GitLab Flow

GitLab Flow представляет собой стратегию работы с feature-ветками и привязку 
веток к этапам развертывания. Разработка ведется в отдельных ветках, а изменения
проходят проверку через Merge Request, а после этого попадают в основную ветку, 
продвигая их при необходимости в окружения.
(ветки разработки + Merge Request + ветки окружений).

## Trunk-Based Development

Это стратегия, при которой основная разработка ведется вокруг одной главной вет-
ки. Разработчики создают очень короткоживущие ветки или небольшие изменения сразу
в основную ветку, не допуская длительного расхождения между ветками.
(одна основная ветка + очень короткие ветки + частые merge).
